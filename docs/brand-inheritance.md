# 브랜드 승계 규칙

> "에어비앤비가 데이팅 앱을 만든다면", "당근이 증권 앱을 만든다면" —
> **그 브랜드가 실제로 만든 것처럼 보이게** 하기 위한 판단 기준.
>
> 이 문서는 **원칙만** 담는다. 색·폰트·간격 같은 **값은 담지 않는다.**
> 값은 매 실행마다 기존 자산 Page에서 실측한다. 심사용 PRD는 미공개다.

---

## 0. 한 문장

> **낯선 문법을 수입하지 말고, 원본의 자리를 승계해서 내용만 갈아끼운다.**

새 기능에 맞는 UI를 "새로 발명"하는 순간 다른 제품이 된다.
원본에 이미 있는 자리를 찾아 거기에 새 의미를 넣는 것이 기본값이다.

---

## 1. 판별 테스트 (기계적)

기존 화면의 모든 요소를 아래 질문 하나로 분류한다.

> **"이 요소에서 원본 도메인 명사를 새 도메인 명사로 바꿔 읽으면, 문장이 성립하는가?"**

| 답 | 분류 | 처리 |
|---|---|---|
| 도메인 명사가 **애초에 없다** | **① 보존** | 값을 실측해 그대로 쓴다 |
| 바꿔 읽으면 **성립한다** | **② 슬롯 승계** | 자리·정렬·위계는 유지, 내용만 교체 |
| 바꿔 읽으면 **말이 안 된다** | **③ 금지** | 가져오지 않는다 |

②를 **최대한 많이** 찾는 것이 목표다. ②가 많을수록 "그 브랜드가 만든 것"처럼 보인다.

### ④ 신규 문법 — 마지막 수단

PRD 필수 요소인데 **승계할 자리가 원본에 없을 때만** 새로 만든다.
그때도 **다른 앱의 문법을 수입하지 않는다.** 원본의 기존 부품을 조합해서 만든다.

> 예: "다음 항목이 뒤에 있음"을 보여야 하는데 원본에 없다
> → 스와이프 덱(타 앱 문법) ✕ / **원본 카드를 하나 더 깔아 단면만 노출** ○

신규 문법은 **화면당 1개 이하**를 목표로 한다. 2개를 넘으면 ②를 덜 찾은 것이다.

---

## 2. ① 보존 — 무엇이 "도메인 명사가 없는" 것인가

아래는 새 기능이 무엇이든 의미가 바뀌지 않는 **순수 시각 문법**이다.
전부 기존 자산 Page에서 **실측**한다. 이 문서에 값을 적지 않는다.

| 실측 항목 | 왜 보존인가 |
|---|---|
| 화면 크기 | 브랜드마다 다르다 (375×812일 수도, 390×844일 수도) |
| 좌우 패딩 · 콘텐츠 폭 | 모든 화면의 정렬 기준선 |
| 간격 스케일 | 여백의 밀도가 브랜드 인상을 만든다 |
| **타이포 스케일** | 사용된 size 종류를 전부 센다 |
| **weight 범위** | **여기가 제일 자주 깨진다.** 실측 범위 밖의 weight는 금지 |
| 라운드 스케일 | 카드용 · 알약용 · 히어로용이 따로 있다 |
| 구획선 두께·색 | 섹션을 나누는 방식 |
| **브랜드색이 나타나는 위치 목록** | 아래 §2-1 참조 |
| 하단 내비 구조 | 탭 개수, 선택 표시 방법 |
| 카드/행의 골격 | 이미지 위치·비율, 텍스트 줄 수와 순서 |
| 정보 위계 순서 | 무엇을 위에, 무엇을 오른쪽 끝에 두는가 |

### 2-1. 🔴 브랜드색 밀도 — 가장 많이 틀리는 지점

**"브랜드답게 = 브랜드색을 칠한다"는 정확히 반대다.**

기존 파일에서 브랜드색이 **몇 번, 어디에** 쓰였는지 세라.
그리고 **그 목록 밖에는 쓰지 마라.** 대부분의 브랜드는 브랜드색을
**면이 아니라 값(텍스트·아이콘·선택 표시)에만** 쓴다.

화면의 색은 브랜드색이 아니라 **사진**이 담당한다.

### 2-2. 보존의 예외 — "정돈"은 허용

PRD는 보통 "정돈은 하되 다른 제품처럼 보이면 안 된다"고 쓴다. 아래는 고쳐도 된다.

- 기존 파일이 **Auto Layout을 안 썼어도** 우리는 쓴다 (구조 점수 항목)
- `Frame 27` 같은 이름은 **의미 기반 이름**으로 바꿔 짓는다
- 간격이 15/16/18처럼 흔들리면 **가장 가까운 스케일로 반올림**한다

시각 결과가 아니라 **데이터 구조**를 정돈하는 것만 허용된다.

## 3. ② 슬롯 승계 — 점수가 나는 구간

원본의 요소를 **"무엇을 하는 자리인가"**로 추상화하면 슬롯이 된다.
슬롯 이름은 원본 도메인 명사를 지운 형태여야 한다.

| 원본 요소 (예) | 슬롯 이름 (도메인 제거) |
|---|---|
| `★4.87 (71 reviews)` | **신뢰 지표 슬롯** — 제목행 우측 끝 |
| `$360 night` | **값 + 단위 슬롯** — 카드 마지막 줄, 강조 |
| 카테고리 아이콘 탭 | **취향 필터 슬롯** — 아이콘 + 라벨 + 선택 밑줄 |
| 아이콘 + 소제목 + 회색 설명 | **팩트 리스트 슬롯** |
| 지도 + 반경 원 | **위치를 흐리게 공개하는 프라이버시 슬롯** |
| 플랫폼 보증 블록 | **안전·보증 설명 슬롯** |
| 규칙·정책 섹션 | **내가 통제하는 설정 슬롯** |
| 자격 배지 | **검증 상태 슬롯** |
| 하단 고정 액션 바 | **결심 액션 슬롯** — 좌: 값 / 우: 주 CTA |
| 상단 검색바 | **현재 상태 요약 + 보조 액션 슬롯** |
| 플로팅 원형 버튼 | **주요 생성 액션 슬롯** |

> 위 표는 **예시일 뿐**이다. 실제 슬롯은 매 실행마다 기존 화면을 읽어 새로 만든다.

### 승계할 때 지키는 것

- **자리와 정렬을 바꾸지 않는다.** 우측 끝에 있던 것은 우측 끝에 둔다.
- **줄 수를 바꾸지 않는다.** 4줄 카드는 4줄로 채운다. 모자라면 내용을 찾는다.
- **자릿수를 맞춘다.** 같은 열의 숫자는 길이를 맞춰야 정렬이 산다.
- 지표를 교체할 때 **원본과 같은 형태**(숫자/배지/아이콘)를 쓰면 리듬이 유지된다.
  형태를 바꾸면(숫자 → 배지) **고정 폭 + 우측 정렬**로 정렬을 방어한다.

## 4. ③ 금지 — 원본 도메인에만 존재하는 것

바꿔 읽으면 말이 안 되는 것. 그대로 두면 **"베꼈다"가 즉시 보인다.**

전형적인 유형:

| 유형 | 예 |
|---|---|
| 원본 거래 단위 | 날짜 범위, 수량 단위, 원본 통화 표기 |
| 원본 물리 속성 | 수용 인원, 설비 개수, 크기·면적 |
| 원본 계약·정책 | 취소·환불·보증 문구 |
| 원본 역할 전환 유도 | "공급자가 되어보세요" 류 배너 |
| 원본 전용 탭 | 새 도메인에 대응 개념이 없는 내비 항목 |
| 원본 인증 체계 | 위치 인증 등 새 도메인과 무관한 검증 |

### 도메인상 성립해도 금지해야 하는 것

**테스트를 통과해도 제품이 망가지는 경우가 있다.** 판단해서 막는다.

> 예: `숙소 평점 4.87` → `사람 평점 4.87` 은 문장은 성립하지만,
> 사람을 점수화하는 제품이 된다. 이런 건 ③으로 내린다.

## 5. 구조 규칙 — 원본이 스스로 정해둔 배타 관계

기존 화면들을 **비교**하면, 원본이 지키는 구조 규칙이 드러난다.
이건 한 화면만 봐서는 안 보인다. **전 화면을 훑어야 나온다.**

찾아야 할 것:

- 어떤 화면에 있고 어떤 화면에 없는가 (예: 하단 내비 ↔ 하단 액션바가 **공존하지 않는다**)
- 그 차이를 가르는 기준은 무엇인가 (예: "둘러보는 화면" vs "결심하는 화면")
- 새로 만들 화면은 그중 **어느 쪽에 속하는가**

이 규칙을 어기면 개별 요소가 다 맞아도 **낯설게** 보인다.
새 화면의 세로 예산이 안 맞을 때, 규칙을 깨서 우겨넣지 말고
**화면의 분류를 다시 판단한다.**

## 6. 실측 시 주의 — 기존 파일을 그대로 믿지 않는다

| 함정 | 대응 |
|---|---|
| **원본 폰트가 서버에 없으면 조용히 대체된다** | `penpot.fonts.all` 로 확인. 없으면 **인상이 가장 가까운 대체 폰트를 정하고 기록**한다. "원본 그대로"라는 선택지는 존재하지 않는다 |
| 대체 폰트 때문에 **텍스트가 잘려** 보인다 | 잘린 문자열을 원문으로 오해하지 않는다. `characters` 값을 직접 읽는다 |
| `export_shape`가 레이아웃 안정 전에 찍힌다 | 비어 보이면 **재-export 한 번** 하고 판단한다 |
| 아이콘 path의 무채색이 **색 집계를 오염**시킨다 | 채도로 거른 뒤, **면적 × 빈도**로 판단한다 |
| 한 화면에만 나오는 값 | 토큰으로 승격하지 않는다. `기타 관측값`에 남긴다 |

## 7. 산출물 계약 — 어느 단계가 무엇을 만드는가

이 문서는 **원칙**이고, 강제는 단계 계약이 한다. 소유 단계는 아래와 같다.
표의 정확한 컬럼은 각 `.agents/skills/stage-*/SKILL.md`의 출력 형식이 정본이다.

| 이 문서의 절 | 소유 단계 | 만드는 표 |
|---|---|---|
| §2 실측, §2-1 브랜드색 밀도 | 2 (레퍼런스만 봄) | `Brand color density`, `Measured primitives` |
| §3 슬롯 추상화 | 2 | `Slot inventory` |
| §5 구조 배타 규칙 | 2 | `Structural exclusivity rules` |
| §1 판별 테스트 ①②③④ | 3 (신규 도메인을 알아야 함) | `Inheritance decision table` |
| §4 금지 판단 | 3 | 같은 표의 `③` 행 |
| §3 승계할 때 지키는 것 (자리·줄 수·자릿수) | 4 명세 → 5 저작 | `Slot fidelity spec` → `Slot fidelity log` |
| §2 보존값 준수 | 4 명세 → 5 저작 | `Preservation budget` |
| 전부 | 6 감사 / 7 검증 | `Inheritance audit` / `Inheritance lineage` |

**분류되지 않은 요소가 남으면 안 된다.** 3단계는 2단계 `Slot inventory`의 모든 행을
①②③④ 중 하나로 판정해야 하며, 미분류가 남으면 3단계를 통과하지 못한다.

### ID 규약

| ID | 의미 | 연결 |
|---|---|---|
| `SLOT-NN` | 2단계가 추출한 도메인 제거 슬롯 | `REF-NN` |
| `SRULE-NN` | 2단계가 찾은 구조 배타 규칙 | `REF-NN` |
| `INH-NN` | 3단계의 승계 결정 한 줄 | `SLOT-NN` + `DEC-NN` |
| `NEW-NN` | ④ 신규 문법 (기존 ID 재사용) | `INH-NN` + `DEC-NN` |

**④는 새 ID 체계를 만들지 않는다.** 하네스의 `NEW-NN`이 곧 ④다.
따라서 ④ 행은 반드시 `NEW-NN`을 가지며, 그 `NEW-NN`은 "어떤 기존 부품을 조합했는가"를
`REF-NN` 목록으로 증명해야 한다. 조합 근거가 없는 ④는 **타 앱 문법 수입**으로 간주한다.

**④가 화면당 2개를 넘으면 ②를 덜 찾은 것이다. 되돌아가 다시 찾는다.**
6·7단계는 이것을 화면 단위로 센다.
