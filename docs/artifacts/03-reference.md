# 03 — 브랜드·레퍼런스 (stage-3-reference 산출)

> 웹 검색 미사용(오프라인 판단). 아래 항목은 **PRD 원문 인용 + ②의 자산 관찰**만을 근거로 한다.
> 도메인 관습 중 출처를 댈 수 없는 것은 **"미조사"**로 남겼다.

## 제품 정체

| key | value | 근거 |
|---|---|---|
| `baseProduct` | 중고거래 플랫폼(동네 기반) | "당근마켓을 만든 팀이" |
| `newDomain` | 증권 서비스 | "**증권 서비스**를 준비하고 있습니다" |
| `targetUser` | 주식을 처음 시작하는 사람 | "주식을 처음 시작하는 사람이 대상입니다" |
| `painPoint` | 숫자 과밀로 첫 화면 이탈 | "화면 하나에 숫자가 수십 개씩 들어가 있어서, 무엇을 봐야 할지 모르는 사람은 첫 화면에서 이탈합니다" |

## 🔴 사용자 리서치 (자산 실측 기반 — 추정 아님)

`1-daangn` 5화면에서 관찰된 **실제 데이터**로 사용자상을 복원했다.

| 관찰 | 근거(자산 원문) | 사용자 함의 |
|---|---|---|
| 거래 금액대가 **4,000원 ~ 1,000,000원** | "4,000원 샌드위치" · "1,000,000원 커피머신" · "220,000원 에어팟 프로" | 생활 밀착 소액. **투자 시드도 소액**에서 시작한다 |
| 모든 정보에 **동(洞) 단위 지역**이 붙음 | "군자동" · "광진구 구의제3동" · "동대문구 휘경동" | 지역은 장식이 아니라 **1차 필터** |
| **매너온도 37.2°C** | 판매자 프로필 | 신뢰를 **숫자 1개**로 압축하는 문법에 익숙 |
| **동네생활**에서 생활 질문을 주고받음 | "Q. 혼밥은 다들 어디서 하시나요?" · "동네질문/동네맛집/같이해요" | 판단이 서지 않을 때 **이웃에게 묻는다** |
| 시간 표기가 "3분 전 · 끌올 1일 전" | 전 화면 공통 | **지금 벌어지는 일**에 반응 |

> 결론: 이 사용자는 *공시를 읽고 밸류에이션을 계산하는 사람*이 아니라
> **"동네 사람들이 뭘 하는지 보고 소액으로 따라 시작하는 사람"** 이다.

## 🔴 왜 당근이 증권을 하는가 (Why — 자산 IA에서 유추)

PRD는 "증권 서비스를 준비한다"고만 말한다. **비즈니스 근거는 자산의 IA에 이미 들어 있다.**

| 자산 근거 (실측) | 유추되는 사업 논리 |
|---|---|
| `나의 당근`에 **당근페이** — "중고거래는 이제 당근페이로 해보세요!" | 결제·송금으로 **돈이 앱 안에 머무는 구조**를 이미 만들었다 |
| `모아보기`에 **당근가계부** | 사용자의 **지출·수입 데이터를 이미 보유** |
| `판매내역` / `구매내역` | 중고거래로 **판 돈**이 정기적으로 발생한다 |
| `관심목록` | 담아두고 지켜보는 행위가 **이미 학습되어 있다** |
| `매너온도` · 동 단위 지역 | 금융의 최대 장벽인 **신뢰**를 커뮤니티로 이미 해결했다 |

**⭐ 핵심 논리 (이 서비스의 존재 이유)**

```
중고거래로 판 돈이 당근페이에 남는다 → 가계부에 여윳돈으로 보인다 → 그 돈의 출구가 없다
                                   ↓
                    "판 돈으로 투자" = 다른 증권사가 만들 수 없는 유입 경로
```

- 다른 증권 앱의 시드머니는 **밖에서 이체**해 와야 한다. 당근은 **앱 안에서 발생**한다.
- 그래서 이 서비스의 첫 화면은 "시장 지수"가 아니라 **"이번 달 판 돈"** 에서 시작해야 한다.
- 종목 추천의 사회적 근거도 "전문가 의견"보다 **"우리 동네 이웃"** 이 먼저다(사용자 리서치 4번).

## 🧭 IA 전략 — 기존 구조를 갈아엎지 않고 얹는다

| 자산의 기존 IA (실측) | 우리 결정 |
|---|---|
| 하단 탭 5개: **홈 · 동네생활 · 내 근처 · 채팅 · 나의 당근** | **그대로 유지한다.** 증권 화면에서도 이 탭바를 쓴다 — 바꾸면 "다른 제품"이 된다 |
| 증권은 어디에 붙는가 | **`나의 당근 → 당근페이 → 투자`** 진입. 즉 증권은 **6번째 탭이 아니라 당근페이의 확장**이다 |
| 증권 내부 이동 | 하단 탭은 당근 것이므로, 증권 3화면은 **상단 컨텍스트 바 + 내부 세그먼트(관심목록/발견)** 로 이동한다 |
| 용어 | **자산의 기존 용어를 그대로 쓴다** — "관심종목"❌ → **"관심목록"**✅ (이미 존재), "매수/매도"에 **"사기/팔기"** 병기, 판매내역 문법 유지 |

## 톤 원칙 5

1. **기존 톤앤매너를 유지한다.** 정돈은 하되 다른 제품처럼 보이면 안 된다.
   — 근거: PRD 조건 "정돈은 하되, 다른 제품처럼 보이면 안 됩니다"
2. **숫자를 줄이고 위계를 세운다.** 한 카드에서 즉시 읽히는 숫자는 **2개**(현재가·등락률)까지.
   — 근거: "숫자가 수십 개씩 … 첫 화면에서 이탈합니다"
3. **부담 없고 익숙한 어투.** 전문용어보다 생활어. 리스트 = 중고거래 목록을 보던 그 감각.
   — 근거: "동네 이웃과 중고거래하듯 **부담 없고 익숙한 경험**"
4. **판단을 대신 내리지 않고 근거를 붙인다.** 추천에는 항상 한 줄 이유.
   — 근거: "정답 하나를 내려주는 화면으로는 안 됩니다" / "추천 결과가 왜 나왔는지 설명이 붙어야 합니다"
5. **선택이 반영된다는 것을 보여준다.** 사용자가 고른 스타일·테마가 결과에 이어져 보여야 한다.
   — 근거: "사용자가 직접 고르게 하고, 그 선택이 추천에 **실제로 반영되는 것처럼 보이게**"

## 신규 도메인 화면 관습

| 관습 | 어디에 | 출처 | 우리 적용 |
|---|---|---|---|
| 상승/하락을 **색으로** 구분 | 리스트·상세 | 도메인 상식 | **적용** (단 색은 자산 팔레트로 — 아래 충돌 해소) |
| 차트 + **기간 전환 탭**(1일/1주/1개월…) | 종목 상세 | PRD 명시 | 적용 |
| **하단 고정 액션**(매수/매도) | 종목 상세 | PRD 명시 | 적용 |
| 주문은 **바텀시트** | 상세 위 | PRD 명시("이 화면 위에 올라오는 형태") | 적용 |
| 컨센서스를 **매수/중립/매도 분포 바**로 | 발견 | PRD 명시 | 적용 |
| 국내 증권앱 상승=빨강·하락=파랑 | — | 도메인 상식 | **미적용** (아래 사유) |
| 종목 로고를 원형 아바타로 | 리스트 | 미조사 | 적용(자산의 원형 radius 100 근거) |

## 🔴 충돌 해소 — 도메인 관습 vs 기존 자산

**규칙: 부딪히면 기존 자산이 이긴다.** 관습은 **레이아웃·정보 위계**에만 적용하고, **색·폰트는 ②의 TOKENS가 SSOT**다.

| 충돌 | 판단 |
|---|---|
| 증권 관습은 상승=빨강/하락=파랑인데, 자산 팔레트에 빨강·파랑이 없다 | **자산 색으로 대체**: 상승 = `accent`(#FF7E36) · 하락 = `accentAlt`(#4AC1DB). 새 색을 들여오면 "다른 제품처럼 보인다"는 조건 위반이 된다 |
| 증권앱은 정보 밀도가 높다 | **톤 원칙 2가 이긴다.** 밀도를 올리지 않고 섹션을 나눠 스크롤로 푼다 |
| 차트는 보통 검정·초록 계열 | 차트 라인도 `semantic.up/down`을 쓴다 |

## 금지 표현·금지 패턴

- **숫자 나열 금지** — 한 행에 숫자 3개 이상 노출 금지(톤 원칙 2 위반)
- **단정형 추천 금지** — "지금 사세요", "급등 임박" 류. 추천은 **이유 한 줄 + 사용자 선택 근거** 형태로
- **공포·긴급 유도 금지** — 카운트다운·붉은 경고 배지 (PRD의 "부담 없고 익숙한" 톤과 충돌)
- **새 브랜드 컬러 도입 금지** — TOKENS 밖의 색을 쓰지 않는다
