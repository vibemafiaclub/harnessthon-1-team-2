# ④ PRD 재작성 — 흩어진 산출물을 하나의 판단 근거 문서로

**왜 이 단계가 있는가.** ①은 화면 목록, ②는 토큰·IA, ③은 톤·Why를 각각 만든다.
이대로 ⑤(화면 스펙)로 가면 **"왜 이 화면이 이렇게 생겨야 하는지"가 파일 3개에 흩어진 채로 남는다.**
사람도 다음 단계 agent도 근거를 못 따라간다. 이 단계는 그걸 **한 문서로 접합**한다.

> 이 문서가 이후 모든 설계 판단의 **인용 출처**가 된다. 화면 스펙·QA는 여기를 근거로 삼는다.

## 입력 (이것만 읽는다)
- `docs/PRD.md` (원본 과제)
- `docs/artifacts/01-screens.md` (화면 인벤토리 · Feature List)
- `docs/artifacts/02-tokens.md` (토큰 · IA · 어휘)
- `docs/artifacts/03-reference.md` (사용자 리서치 · Why · IA 전략 · 톤)

넷 중 하나라도 없으면 **즉시 중단하고 무엇이 없는지 보고**한다.

## 출력 (이것만 쓴다)
- `docs/artifacts/00-prd-{도메인slug}.md`

## 5부 구성 (섹션·순서를 지킨다)

| 부 | 내용 | 어디서 오는가 |
|---|---|---|
| **1. 배경 및 목적** | 1-1 배경 / 1-2 목적 / **1-3 왜 이 회사가 이걸 하는가** / 1-4 타깃 퍼소나 표 | PRD 배경 + ③의 Why·사용자 리서치 |
| **2. 솔루션 및 기능** | 2-1 핵심 솔루션 **한 문장** / 2-2 Feature List 표(이름·설명·우선순위·**근거**) | ①의 Feature List |
| **3. 서비스 구조** | 3-1 IA(**기존 글로벌 내비 실측표** + 신규 진입 경로 + **어휘 사전**) / 3-2 User Flow(문장 + **mermaid**) | ②의 IA·어휘 + ③의 IA 전략 |
| **4. 디자인 전략** | 4-1 레퍼런스 분석(**무엇을 왜 차용**) / 4-2 GUI 톤&매너 + **왜** + 금지 항목 + 토큰 요약 | ③의 톤·관습·금지 + ②의 TOKENS |
| **5. 기술 스펙 체크** | 기능별 DB 설계 + 필요 API + 주의점 | 2-2의 `High` 기능 |

### 각 부의 필수 규칙

1. **모든 주장에 근거를 단다.** PRD 원문 인용 또는 자산 실측값. 근거 없는 문장은 쓰지 않는다.
2. **1-3(Why)은 생략 불가.** ③이 도출한 *`기존 행동 → 남는 자산 → 신규 도메인 입구`* 경로를
   도식으로 넣고, **"경쟁사가 복제할 수 없는 이유"** 를 1줄로 못 박는다.
   → 이 경로가 **첫 화면 최상단 섹션**을 결정한다는 문장을 명시한다.
3. **2-2 Feature List의 `High` = P0 화면의 필수요소**와 1:1로 이어져야 한다.
4. **3-1에 기존 글로벌 내비 실측표를 그대로** 넣고, *"신규 기능은 N+1번째 탭이 아니다"* 를 명시한다.
5. **3-1 어휘 사전**: `일반 도메인 용어 → 이 제품의 기존 용어` 대응표. 신조어 금지.
6. **3-2는 문장 플로우 + mermaid `flowchart TD`** 둘 다. 실패·빈 상태 분기를 반드시 포함한다.
7. **4-1은 "무엇을 왜 차용하는지"** 가 핵심이다. 레퍼런스 나열만 하면 안 된다.
   일반 도메인 레퍼런스는 **레이아웃만 차용하고 색·타이포는 자산 토큰**이라고 명시한다.
8. **4-2에 금지 항목**(새 브랜드 컬러·단정형 표현·공포 유도 등)을 남긴다 → ⑦ QA의 감점 체크리스트가 된다.
9. **5부는 `High` 기능만.** PRD 5절 성격(실패·빈 상태)에서 나온 에러 코드를 API 실패 응답과 1:1로 맞춘다.

## 브랜드 아이덴티티 보강 (선택 — 공개 채널이 있을 때)

제품의 **공식 소개 채널**(웹사이트·앱스토어 설명)이 있으면 아래를 확보해 §1·§4에 반영한다.
없거나 접근 불가면 **"미조사"** 로 남기고 자산 관찰만으로 진행한다.

| 확보할 것 | 쓰임 |
|---|---|
| **슬로건·태그라인** | 신규 서비스의 카피 문장 구조를 여기서 파생(같은 문법이면 같은 제품으로 읽힌다) |
| **서비스 카테고리 목록** | 신규 도메인과 **인접한 기존 사업**을 찾는다 → Why 근거 보강 |
| **반복 가치어** | 톤 원칙과 금지 표현의 근거 |

## 출력 검증 (스스로 확인하고 통과 못 하면 다시 쓴다)
- [ ] 1-3 Why 경로 도식이 있고, 첫 화면 최상단 섹션을 지정했는가
- [ ] Feature List의 `High` 개수 ≥ P0 화면 수
- [ ] 3-1에 **실측 글로벌 내비 표**와 **어휘 사전**이 있는가
- [ ] 3-2 mermaid에 **실패/빈 상태 분기**가 있는가
- [ ] 4-2에 **금지 항목**이 있는가
- [ ] 근거 없는 단정 문장이 0개인가

## 금지
- 시장 데이터·통계를 **지어내지 않는다.** 근거는 PRD·자산·공식 채널뿐이다.
- 특정 PRD 고유명사를 **지침에** 박지 않는다(산출물에 값으로 들어가는 것은 정상).
- 화면 레이아웃을 여기서 정하지 않는다(그건 ⑤의 몫).
- 다른 단계의 출력 파일을 쓰지 않는다.
