# 브랜드 적응형 PRD-to-Penpot 하네스

## 목표

현재 Penpot 파일 안의 회사 레퍼런스를 읽고, 그 회사의 식별 가능한 디자인 특징은 유지하면서 전혀 다른 신규 PRD의 과업·콘텐츠·상태에 맞는 UI를 만든다. 원본 제품을 복제하거나 범용 템플릿에 로고색만 입히는 결과는 모두 실패로 본다.

## 실행 입력

| 키 | 규칙 |
|---|---|
| `prd_path` | 신규 제품 PRD. 기본값 `docs/PRD.md` |
| `work_page` | 저작할 개인 Page. 필수이며 추측 금지 |
| `reference_pages` | 정확히 하나의 `primary`와 선택적 `supplemental` Page |
| `brand_context_path` | 선택적 브랜드·카피 보조 문서 |
| `run_id` | 실행 식별자. 생략 시 타임스탬프 기반 생성 |
| `artifact_dir` | `docs/artifacts/<run_id>` |

`primary`는 계승할 회사 정체성을 결정한다. supplemental은 특정 패턴만 참고하며 primary보다 우선할 수 없다. 현재 Penpot 플러그인은 열린 파일 밖을 볼 수 없으므로 모든 Page는 현재 파일 안에 있어야 한다.

## 7단계 계약

| # | 단계 | 핵심 판단 | 출력 |
|---|---|---|---|
| 1 | 제품 요구 계약 | 새 제품이 반드시 해결할 과업·상태·수용 조건 | `01-prd-contract.md` |
| 2 | 브랜드 레퍼런스 포렌식 | 무엇이 회사 고유 특징이고 무엇이 원래 사업 종속 패턴인지 | `02-reference-system.md` |
| 3 | 브랜드 적응형 UX | 어떤 특징을 보존·변환하며 새 과업의 흐름을 어떻게 구성할지 | `03-experience-map.md` |
| 4 | 근거 기반 UI 시스템 | 판단을 어떤 토큰·컴포넌트·수치·카피로 저작할지 | `04-ui-blueprint.md` |
| 5 | Penpot 저작 | 블루프린트를 실제 구조와 화면으로 정확히 구현했는지 | `05-author-log.md` |
| 6 | 이중축 비평·수정 | PRD 적합성과 브랜드 충실도가 각각 충분한지 | `06-visual-qa.md` |
| 7 | 독립 최종 검증 | 파일·노드·PNG에서 세 계보가 모두 입증되는지 | `99-verify.md` |

## DAG

```text
1. 제품 요구 계약 ─────────┐
                           ├─> 3. 브랜드 적응형 UX
2. 브랜드 포렌식 ─────────┘
      -> 4. UI 시스템
      -> 5. Penpot 저작
      -> 6. 이중축 비평·수정
      -> 7. 독립 최종 검증
```

1단계와 2단계는 병렬이다. Penpot을 변경하는 5단계와 6단계는 반드시 직렬이다.

blocking open question이 있으면 사용자 답을 받기 전 중단한다. 검증 실패 시 해당 단계만 다시 돌리지 않고 그 단계에 의존하는 후속 closure 전체를 재실행한다. Penpot 재저작은 기존 author log의 node ID를 기준으로 제자리 갱신하며, 호환되지 않는 이전 보드는 삭제하지 않고 `Archive/<run_id>/<revision_id>/`로 격리한다.

## 세 추적 계보

| 계보 | 증명하는 것 |
|---|---|
| `REQ-NN → 화면/상태 → 노드` | 신규 PRD가 빠짐없이 구현됨 |
| `REF-NN → DEC-NN → 토큰·컴포넌트·노드` | 회사 특징이 근거 있게 계승됨 |
| `SLOT-NN → INH-NN → 분류 → 노드` | 원본의 모든 자리가 승계·금지·신규 중 하나로 판정됨 |
| `NEW-NN → DEC-NN → 토큰·컴포넌트·노드` | 레퍼런스에 없던 해법도 임의적이지 않음 |

## 브랜드 승계 규칙

`docs/brand-inheritance.md`가 판단 기준이다. 값은 담지 않고 원칙만 담으므로 PRD가 바뀌어도 그대로 쓴다.
2단계가 슬롯·브랜드색 밀도·구조 배타 규칙을 실측하고, 3단계가 신규 도메인을 알고 나서 ①보존 ②슬롯 승계 ③금지 ④신규 문법으로 판별한다. 4단계가 자리·정렬·줄 수와 실측 범위를 수치로 강제하고, 6·7단계가 감사한다.

## 자동 실패

- 필수 요구나 상태 누락
- primary의 signature가 화면에서 보이지 않음
- supplemental 스타일이 primary를 압도함
- 원본 제품의 IA·카피·사업 개체를 이름만 바꿔 복제함
- 핵심 시각 결정에 레퍼런스나 도출 근거가 없음
- 판별되지 않은 원본 요소(`SLOT-NN`) 잔존, 또는 한 화면의 신규 문법이 2개 초과
- 최종 PNG export 누락
- QA의 blocker 또는 major 잔존
