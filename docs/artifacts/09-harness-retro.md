# 09 — 하네스 회고: 오늘 무엇이 무너졌고, 무엇을 덧댔는가

2026-08-01 · 당근증권 + 토스여행 2개 프로젝트 실행 후 · 디자이너(수민·소현) 협업 기준

---

## 0. 오늘의 결론 3줄

1. **하네스는 처음부터 완성되지 않는다.** 초안을 돌려서 *무너지는 지점*을 보고, **딱 그 영역만 덧대는 것**이 하네스 제작의 본체다.
2. **모든 단계에 최고 모델을 쓸 이유가 없다.** 판단이 필요한 곳만 상위 모델, 규칙이 정해진 검수는 Sonnet, 기계적 반복은 Haiku.
3. **가장 중요한 건 "디자이너가 어떤 순서로 일하는가"** 다. 그 순서가 단계로 들어와 있지 않으면, 아무리 도구가 좋아도 결과물은 초안에서 멈춘다.

---

## 1. 초안 하네스 vs 실제로 필요했던 것

초안(오전): `①PRD해부 → ②자산토큰 → ③레퍼런스 → ④스펙 → ⑤저작 → ⑥QA → ⑦검증`

돌려보니 **⑤저작이 만든 결과물이 디자이너 기준에 한참 못 미쳤다.** 그런데 ⑥QA는 그걸 못 잡았다.
QA가 "4항목 1~5점"이라는 **추상 루브릭**이었기 때문이다. 디자이너의 지적은 훨씬 구체적이었다.

### 디자이너가 실제로 지적한 것 → 초안 하네스에 없던 것

| # | 실제 지적 (원문) | 무너진 지점 | 초안에 있었나 |
|---|---|---|---|
| 1 | *"당근스러운 느낌이 없다"* | 토큰만 뽑고 **IA·어휘·정보축**을 안 뽑음 | ❌ ②가 색/폰트만 |
| 2 | *"주황이 남발되어 어디에 집중할지 모르겠다"* | **컬러 규율**(강조색 사용 면적) 부재 | ❌ |
| 3 | *"글자가 상단에 붙고 줄바뀜이 불편"* | `verticalAlign` 기본 top · 텍스트 폭 미조정 | ❌ |
| 4 | *"마진값 특히 위아래가 일정하지 않다"* | **스페이싱 규칙 미고정** | ❌ |
| 5 | *"이 이미지가 무엇을 표현하는지 이해 못 하겠다"* | 일러스트 **직관성 검수** 없음 | ❌ |
| 6 | *"그래프 디자인이 너무 구리다 · 주식스럽게"* | **도메인 표현 적절성** 검수 없음 | ❌ |
| 7 | *"동네주식방이 앞선 디자인과 통일성이 없다"* | **화면 간 일관성** 검수 없음 | ❌ |
| 8 | *"기존 이모티콘 그대로 크롤링해서 넣어라"* | **실물 에셋 조달** 단계 없음 | ❌ |
| 9 | *"상하단 쪽 디자인시스템 적용이 안 된다"* | **시스템 적용 완전성** 검수 없음 | ❌ |
| 10 | *"레퍼런스 구성을 피드백하라는 것이지 그대로 만들라는 게 아니다"* | **비판적 차용** 원칙 부재 | ❌ |

→ **10건 중 10건이 초안 하네스에 없었다.** 이것이 "초안을 돌려봐야 아는 것"의 실체다.

**원칙: 초안이 못 하는 게 확인된 그 영역에만, 그 시점에 단계를 만든다.** 미리 다 만들지 않는다.

## 3. 모델 티어링 — 최고 모델은 판단에만

오늘 전 단계를 상위 모델로 돌렸는데, **절반은 그럴 필요가 없었다.**

| 단계 | 하는 일의 성격 | 모델 | 이유 |
|---|---|---|---|
| ① PRD 해부 | 문장→화면 환원, **의미 판단** | `opus` | 절 성격 추론·암시 화면 도출은 추론 난이도가 높다 |
| ② 자산 토큰·IA | 스캔은 기계적, **해석**이 조금 | `sonnet` | 코드가 값을 뽑아준다. 모델은 정리만 |
| ③ 레퍼런스·Why | **가장 어려운 판단** (왜 이 회사가 이걸 하는가) | `opus` | 여기가 결과물의 질을 가른다 |
| ④ PRD 작성 | 앞 산출물 **접합·문서화** | `sonnet` | 형식이 정해져 있다 |
| ⑤ 화면 스펙 | 규칙 적용 + 약간의 설계 | `sonnet` | 토큰·컴포넌트가 이미 정해짐 |
| ⑥ 저작 | 코드 실행 + **함정 회피 판단** | `opus` | 실패 복구·구조 판단이 계속 필요 |
| ⑦ QA | 이미지 보고 **루브릭 대조** | `sonnet` | 기준이 문서화돼 있으면 충분 |
| ⑧ 에셋 채움 | 플레이스홀더 탐지 + SVG 생성 | `sonnet` | 오늘 실제로 Sonnet으로 돌려서 성공 |
| ⑨ 검증 | 되읽기 + 목록 대조 | `haiku` | 완전 기계적 |
| 파일 정리·리네이밍·크롭 | 반복 작업 | `haiku` | 판단 0 |

**오늘 실증**: ⑧ asset-fill을 Sonnet으로 돌려 플레이스홀더 20+건 탐지, SVG 7종 생성, 매니페스트 작성까지
정확히 수행했다. **상위 모델을 쓸 이유가 전혀 없었다.**

> 판단 기준: **"틀렸을 때 되돌리기 비싼가?"**
> 비싸면 상위 모델(설계·저작), 싸면 하위 모델(검수·정리·생성).

## 4. ⭐ 핵심 — 디자이너의 프로세스가 하네스에 녹아 있는가

오늘의 진짜 교훈. 도구가 아니라 **일하는 순서**가 하네스다.

### 디자이너의 실제 프로세스 (소현님 PRD + 수민님 피드백에서 복원)

```
① 왜 만드는가 (배경·목적·퍼소나)
② 무엇을 참고하는가 — 레퍼런스를 모으고 "무엇을 왜 차용할지" 판단
③ 어디에 붙는가 (IA·유저플로우)
④ 무엇으로 그리는가 (디자인 시스템: 색·타이포·스페이싱·컴포넌트)
⑤ 그린다
⑥ 본다 — 정렬·여백·톤·일관성·빈자리
⑦ 고친다 → ⑤로
```

### 우리 하네스와의 매핑 (오늘 보완 후)

| 디자이너 단계 | 하네스 단계 | 오늘 상태 |
|---|---|---|
| ① 왜 만드는가 | ① PRD 해부 + ③ **Why 도출** | ✅ 보완 완료 (초안엔 Why가 없었다) |
| ② 무엇을 참고하는가 | ③ 레퍼런스 — **삼각측량** + 비판적 차용 | ✅ 보완 완료 |
| ③ 어디에 붙는가 | ② IA 추출 + ③ IA 전략 | ✅ 보완 완료 |
| ④ 무엇으로 그리는가 | ② 토큰 + **05 디자인시스템(M3)** | ✅ 보완 완료 |
| ⑤ 그린다 | ⑥ 저작 | ✅ 처음부터 있었음 |
| ⑥ **본다** | ⑦ QA + ⑧ 에셋채움 + (미구현 ⑨일관성·⑩도메인) | ⚠️ **가장 약한 고리** |
| ⑦ 고친다 | 저작 재실행 | ✅ |

**⑥ '본다'가 하네스의 최대 약점이었다.** 디자이너는 화면을 보면 10초 만에 잡는 것을,
우리 QA는 "완성도 3점" 같은 말로만 적고 넘어갔다. → 검수를 **추상 점수에서 구체 체크리스트로** 바꿔야 한다.

### 레퍼런스 삼각측량 (오늘 발견한 가장 효과적인 방법)

한 곳만 보면 복제가 되고, 세 곳을 보면 **판단**이 생긴다.

| 축 | 무엇을 얻나 | 당근증권 사례 | 토스여행 사례 |
|---|---|---|---|
| **1. 과제의 기존 자산** | 색·폰트·IA·어휘 (SSOT) | `1-daangn` | `3-toss` |
| **2. 같은 회사의 인접 서비스** | **그 회사가 이 도메인을 어떻게 푸는가** | 당근 **부동산** 실거래가 | 토스 **쇼핑** |
| **3. 도메인 1위 앱** | 도메인 관습(레이아웃만 차용) | **토스증권** | **NOL 여행** |

- 축 2가 결정적이었다. 당근 부동산이 이미 *"큰 숫자 + 직전 최고가 대비 + 지역 필터"* 를 풀어놨고,
  그게 증권 화면의 답이었다. **같은 회사의 인접 서비스를 안 보면 반드시 남의 앱이 된다.**
- 축 3은 **레이아웃만** 가져오고 색·타이포는 축 1을 따른다.

### 비판적 차용 — 복제와 무엇이 다른가

> 디자이너: *"레퍼런스의 구성을 피드백하라는 거지, 그대로 만들라는 게 아니었다."*

**복제**: NOL 홈에 카테고리 10개 그리드가 있으니 우리도 10개.
**비판적 차용**: *"카테고리 10개는 백화점식 진열이다. 토스는 홈에 계좌 5개, 혜택에 미션 5개만 두는
**선택을 좁혀주는 앱**이다."* → **4개 + 전체보기**로 줄이고, 최상단을 **여행 저금통**으로 교체.

⇒ 스펙 단계에 넣을 질문: **"이 구성은 우리 제품의 어떤 원칙과 충돌하는가?"**

## 5. 다음 라운드에 반영할 것

1. **⑦ QA를 구체 체크리스트로 교체** — 아래 10항목(=디자이너가 실제로 지적한 것)
   - [ ] 브랜드 정체성: 색만 같고 문법은 남의 앱인가
   - [ ] 강조색 규율: 화면당 주색 면적 1곳 + 활성 상태
   - [ ] 텍스트 정렬: `verticalAlign` · 단어 중간 줄바꿈
   - [ ] 스페이싱: 좌우 마진 고정 · 섹션 상하 동일 · 4dp 배수
   - [ ] 상·하단 시스템: top bar 높이 · nav bar 높이 · 하단 여백
   - [ ] 플레이스홀더 0: 단색 사각형이 남아 있는가
   - [ ] 실물 에셋: 아이콘·로고가 진짜인가
   - [ ] 화면 간 일관성: 같은 요소가 화면마다 다르게 생겼는가
   - [ ] 도메인 표현: 차트·지도가 그 도메인답게 생겼는가
   - [ ] 카피 톤: 그 앱의 UX 라이팅 문법인가
2. **모델 티어를 각 agent frontmatter에 명시** (`model: opus|sonnet|haiku`)
3. **⑨ 일관성 감사 / ⑩ 도메인 충실도** 는 다음에 무너지면 그때 만든다
