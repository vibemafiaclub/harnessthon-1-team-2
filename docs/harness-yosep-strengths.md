# Yosep 브랜치 강점과 범용 하네스 이식 원칙

`origin/yosep`의 당근증권 실행 결과를 그대로 합치지 않고, 어느 회사·PRD에도 적용되는 실행 규칙만 현재 하네스에 이식한다. 이 문서는 실행 산출물이 아니라 하네스 설계 근거다.

## 유지할 현재 하네스의 기반

- 실행별 `run_id`와 `artifact_dir` 격리
- primary 레퍼런스 하나를 중심으로 한 `REF → DEC → node` 계보
- 브랜드 혼입·원본 제품 복제 방지, 작업 Page 안전 게이트
- PRD 요구·상태·수용 조건과 실제 Penpot 노드의 독립 검증

## 이식할 Yosep 강점

| 강점 | 범용 이식 규칙 | 적용 위치 |
|---|---|---|
| PRD 문장을 화면으로 환원 | 명시 화면뿐 아니라 행동의 목적지, 성공·실패·복구, 빈·로딩·오류 상태를 화면/오버레이 후보로 만든다. | 1단계 |
| 우선순위 | 요구를 P0~P3로 분류해 P0/P1을 먼저 저작·QA하고, 동일 성격의 저우선 상태는 통합 표현한다. | 1·3·5·6단계 |
| 실측 토큰 추출 | 미세 도형을 제외하고, 색·폰트·간격·아트보드 크기를 역할과 반복 표본으로 해석한다. 폰트는 실제 가용성을 확인한다. | 2·4·5단계 |
| IA·용어 보존 | 색상뿐 아니라 navigation, 메뉴 계층, 반복 용어, 신뢰 정보 축을 조사해 새 도메인에서 의미에 맞게 번역한다. | 2·3·4단계 |
| 저작 안전성 | Page 전환과 저작을 분리하고, 매 저작 호출에서 target Page drift와 소유 노드를 확인한다. | 5단계 |
| 재실행 안전성 | 실행 소유권이 있는 노드만 reconcile하고, 중복 생성·위험한 rename/remove를 피한다. | 5단계 |
| PNG 기반 QA | 코드·로그가 아니라 export 이미지를 보고, PRD 충족·브랜드·구조·시각 완성도를 함께 판정하며 종료 조건을 둔다. | 5·6·7단계 |

## 이식하지 않는 것

- 당근증권 고유 화면명, 카피, 색상, 자산, `AUTHOR-all-screens.js`
- 루트 `docs/artifacts/` 고정 경로와 실행 결과를 다음 실행의 입력으로 재사용하는 방식
- 특정 도메인의 가격·보상·사용자 정책을 기본값으로 두는 방식
- 실행 DAG에 연결되지 않은 별도 단계

## PRD 미정값 처리 원칙

하네스는 도메인별 질문을 반복하지 않는다. `assumption_mode=auto`에서 PRD의 미정값은 아래처럼 처리한다.

| 분류 | 처리 | 화면/산출물 표기 |
|---|---|---|
| 명시 요구 | 원문 그대로 구현 | `REQ-NN` |
| 표현값 공백 | 일관된 예시 데이터·수치·카피를 생성 | `ASM-NN`, `예시` 또는 프로토타입 표기 |
| 세부 정책 공백 | 최소 가정을 명시하고, 교체 가능한 컴포넌트·카피로 구현 | `ASM-NN`, 정책 미확정으로 오인되지 않게 범위 표기 |
| 구현 안전 공백 | 작업 Page, primary 레퍼런스, 파일 접근처럼 잘못 추측하면 외부 상태를 훼손하는 입력만 중단하고 확인 | `BLOCK-NN` |

가정은 실제 정책·가격·성능·법적 보장처럼 단정하지 않는다. 반드시 해당 화면 노드까지 계보를 남기고 QA/검증에서 가정 표기와 PRD 충돌 여부를 확인한다.
