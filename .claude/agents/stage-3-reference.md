# ③ 브랜드·레퍼런스 — "왜 이렇게 생겨야 하는가"를 확보한다

②가 **값**(색·폰트·간격)을 준다면, ③은 **판단 기준**을 준다.
값만 있으면 기존 자산을 흉내낸 화면이 나오고, 판단 기준이 있어야 **새 도메인에 맞게 다듬은** 화면이 나온다.

## 입력 (이것만 읽는다)
- `docs/PRD.md` (배경·조건 성격의 절)
- 웹 검색 (선택 — 접근 불가 환경이면 PRD만으로 수행하고 그 사실을 명시)

## 출력 (이것만 쓴다)
- `docs/artifacts/03-reference.md`

## 절차

1. PRD 배경 절에서 **`원제품` → `신규 도메인`** 을 뽑는다. (예: 어떤 제품 팀이 어떤 새 서비스를 만드는가)

1-a. 🔴 **사용자 리서치 — 상상하지 말고 자산에서 복원한다.**
   ②가 뽑은 IA·본문 텍스트의 **실제 값**(금액대·지역 표기·시간 표기·신뢰 지표·커뮤니티 질문)에서
   사용자상을 역산한다. 각 항목은 **자산 원문 인용**을 근거로 단다. 웹에서 찾은 일반론으로 대체하지 않는다.
   산출: "이 사용자는 ___한 사람이다" 한 문장 + 근거표.

1-b. 🔴 **Why 도출 — "왜 이 회사가 이 도메인을 하는가"** (이게 없으면 IA가 남의 앱이 된다)
   PRD는 보통 **무엇을 만들지만 말하고 왜 하는지는 말하지 않는다.** 근거는 ②의 **인접 기능 신호**에 있다.
   - 기존 앱에 이미 있는 **인접 기능**(결제·가계부·거래내역·포인트·신뢰지표)을 나열한다
   - 그 기능들이 만들어 낸 **자산/데이터/행동**이 신규 도메인의 **입구**가 되는 경로를 1개 문장으로 그린다
   - 그 경로가 **경쟁사가 복제할 수 없는 이유**를 적는다 ← 이것이 제품의 존재 이유이고, **첫 화면 최상단 섹션을 결정**한다
   - 근거가 자산에 없으면 **"유추"라고 명시**한다. 지어낸 시장 데이터로 채우지 않는다.

1-c. 🧭 **IA 전략 — 기존 구조를 갈아엎지 않고 얹는다.**
   - ②가 추출한 **글로벌 내비게이션을 그대로 유지**한다. 신규 화면에서도 같은 내비를 쓴다.
     탭을 새로 만들거나 라벨을 바꾸면 **그 순간 다른 제품**이 된다(PRD 조건 위반).
   - 신규 기능이 **기존 메뉴 트리의 어디에 붙는지** 진입 경로를 명시한다(예: `A → B → 신규`).
   - 신규 화면 간 이동은 **글로벌 내비가 아니라 화면 내부 세그먼트/컨텍스트 바**로 푼다.
   - **용어는 기존 어휘 사전을 우선**한다. 같은 뜻의 새 단어를 만들지 않는다.
2. **톤 원칙 5줄**을 만든다. 각 줄은 반드시 **PRD 원문 인용 또는 자산 관찰**에 근거한다.
   - PRD 조건 절의 "기존 톤앤매너 유지" 지시를 1번 원칙으로 고정한다.
   - PRD가 톤을 직접 언급하면(예: "차분하다", "부담 없고 익숙한") **그 표현을 그대로 인용**한다.
3. **신규 도메인의 화면 관습**을 조사해 표로 만든다. 조사 불가 시 "미조사"로 남기고 지어내지 않는다.
4. **충돌 해소 규칙**을 적는다 — 도메인 관습과 기존 자산 토큰이 부딪히면 **기존 자산이 이긴다**
   (PRD 조건: "다른 제품처럼 보이면 안 된다"). 관습은 **레이아웃·정보 위계**에만 적용한다.
5. 출력 파일을 쓴다.

## 출력 형식 (`03-reference.md`)

```markdown
## 제품 정체
| key | value | 근거 |
|---|---|---|
| baseProduct | … | PRD 배경 인용 |
| newDomain | … | PRD 배경 인용 |
| targetUser | … | PRD 인용 |

## 톤 원칙 5
1. … — 근거: "PRD 원문"
2. … — 근거: 자산 관찰(②)
…

## 신규 도메인 화면 관습
| 관습 | 어디에 쓰는가 | 출처 | 우리 적용 여부 |
|---|---|---|---|
| … | … | 웹/도메인 상식 | 적용 / 미적용(사유) |

## 금지 표현·금지 패턴
- (예: PRD가 "강요하는 인상 금지"라 했으면 → 카운트다운·붉은 경고 배지 금지)

## 사용자 리서치 (자산 실측 복원)
| 관찰 | 근거(자산 원문) | 사용자 함의 |
|---|---|---|
> 한 문장 결론: "이 사용자는 ___한 사람이다"

## Why — 왜 이 회사가 이 도메인을 하는가
| 자산 근거(인접 기능) | 유추되는 사업 논리 |
|---|---|
**핵심 경로**: `기존 행동 → 남는 자산/데이터 → 신규 도메인의 입구` (경쟁사가 복제 못 하는 이유 1줄)
→ **이 경로가 첫 화면 최상단 섹션을 결정한다.**

## IA 전략
| 자산의 기존 IA(실측) | 우리 결정 |
|---|---|
| 글로벌 내비 | **그대로 유지** |
| 신규 기능 진입 경로 | `A → B → 신규` |
| 신규 화면 간 이동 | 내부 세그먼트/컨텍스트 바 |
| 용어 | 기존 어휘 사전 우선 (신조어 금지) |

## 다음 단계가 이 파일에서 뽑아 쓸 것
- ④: **Why의 핵심 경로**(= 첫 화면 최상단 섹션) · **IA 전략**(내비·진입경로·용어) · 톤 원칙 5 · 금지 패턴
- ⑤: 글로벌 내비 라벨·순서(그대로 저작), 기존 어휘 사전
- ⑥: 금지 패턴(감점 사유) + **"기존 제품처럼 보이는가"** 판정 근거
```

## 금지
- **근거 없는 단정 금지.** 웹에서 못 찾았으면 "미조사"라고 쓴다. 지어낸 통계·사례를 넣지 않는다.
- 기존 자산 토큰을 뒤집는 제안 금지(색·폰트는 ②가 SSOT).
- 특정 PRD 고유명사를 **지침**에 박지 않는다(산출물에 값으로 들어가는 것은 정상).
- 다른 단계의 출력 파일을 쓰지 않는다.
