# ① PRD 해부 — 문장을 화면 목록으로 환원한다

## 입력 (이것만 읽는다)
- `docs/PRD.md`

## 출력 (이것만 쓴다)
- `docs/artifacts/01-screens.md`

## 🔴 절 번호로 파싱하지 않는다 (재현성 1순위)

PRD마다 절 번호가 다르다(같은 "만들어야 할 화면"이 어떤 PRD는 6절, 어떤 PRD는 7절).
**번호가 아니라 절의 성격으로 찾는다.**

| 찾을 것 | 단서 (성격) | 없으면 |
|---|---|---|
| `assetPage` — 읽을 기존자산 Page | "기존 자산" 성격의 절에서 **백틱으로 감싼 Page 이름**. "다른 과제니 읽지 말라"는 경고 대상은 **제외** | 중단하고 사용자에게 묻는다 |
| `framePrefix` — 제출 프레임 네이밍 | "제출" 성격의 절. 예: "최상위 프레임 이름은 `New/` 로 시작" | 접두어 없음으로 두고 명시 |
| `screenNames` — PRD가 지정한 화면 이름 | 제출 절의 나열 + 화면 절의 백틱 이름 | slug에서 PascalCase 파생 |
| `minScreens` — 화면 하한 | "최소 N개" 표현 | 3으로 두고 명시 |
| `mustHave` — 화면별 필수 요소 | 화면 절의 "필수 요소" 목록 | 그 화면은 P0에서 제외하고 보고 |

## 절차

1. `docs/PRD.md`를 읽는다. 없으면 **즉시 중단하고 보고**한다.
2. 위 표의 전역 파라미터를 추출한다. `assetPage`를 못 찾으면 **추측하지 말고 중단**한다.
3. **명시 화면**을 뽑는다 — 화면 절이 제목으로 요구한 것 전부. 전부 **P0**.
4. **암시 화면**을 뽑는다. 유저스토리·상황 절의 문장을 아래 규칙으로 환원한다.
   - "…하고 **그 결과를 확인**하고 싶다" → **결과 화면**
   - "**진입점**"이 필수 요소면 → 그 **목적지 화면**
   - "정렬/필터 **진입점**" → 눌렀을 때 뜨는 **시트**
   - "아직 아무것도 담지/입력하지 않은" → **빈 상태**
   - "몇 초가 걸린다 / 아직 들어오지 않는" → **로딩 상태**
   - "실패하는 경우가 있다 / 모자란 상태" → **에러 상태**
   - 근거 문장을 **원문 그대로 인용**해 남긴다. 인용 없는 화면은 만들지 않는다.
5. 각 화면에 **우선순위 등급**을 매긴다.

| 등급 | 정의 | 저작 정책 |
|---|---|---|
| **P0** | PRD가 화면 절에서 **명시**한 것 | 무조건 만든다 |
| **P1** | 없으면 **주 플로우가 끊기는** 상태 (결제 실패, 결과 없음, 미로그인 등) | P0급 필수 |
| **P2** | 도메인 관습상 있을 법하나 없어도 플로우는 도는 것 | **예산 남을 때만** |
| **P3** | 여러 화면에 반복되는 같은 성격의 상태(빈/로딩/에러) | **화면마다 만들지 않는다.** `S9x-states` 보드 1장에 통합 |

5-b. 🔴 **화면 이전에 기능 목록(Feature List)을 먼저 만든다.**
   화면으로 바로 건너뛰면 "PRD에 적힌 화면"만 나오고 **그 화면이 무슨 기능을 담는지**가 비어 있다.
   - 각 기능: `이름 · 설명 · 우선순위(High/Medium/Low) · 근거(PRD 인용 또는 자산 관찰)`
   - **`High` 기능이 P0 화면의 필수요소가 된다.** 화면 ↔ 기능 매핑을 남긴다.
   - PRD에 없지만 ③의 Why에서 도출된 기능(제품의 존재 이유를 구현하는 기능)은 **`High`로 올린다.**
6. slug를 부여한다: `S{2자리}-{케밥영문}`. **slug ↔ 제출 프레임명 매핑을 반드시 남긴다.**
   - 제출 프레임명 = `{framePrefix}{PRD가 지정한 이름}` (지정명을 **그대로**, 창작 금지)
7. 출력 파일을 쓴다.

## 출력 형식 (`01-screens.md` — 다음 단계가 파싱한다)

```markdown
## 전역 파라미터
| key | value | 근거(PRD 원문 일부) |
|---|---|---|
| assetPage | {백틱 Page 이름} | "읽을 대상: …" |
| framePrefix | New/ | "최상위 프레임 이름은 …" |
| minScreens | 3 | "최소 3개" |
| doNotRead | {읽지 말라고 경고된 Page} | "다른 과제의 기존 파일" |

## 화면 인벤토리
| slug | 제출 프레임명 | 등급 | 목적 | 필수 요소 | 근거(원문 인용) |
|---|---|---|---|---|---|
| S01-… | New/… | P0 | … | - …<br>- … | "…" |

## 플로우
S01 →(진입점: …)→ S02 →(주문 확정)→ S03

## 다음 단계가 이 파일에서 뽑아 쓸 것
- ②: `assetPage`, `doNotRead`
- ④: 화면 인벤토리 전체(필수 요소가 스펙의 체크리스트가 된다)
- ⑤: `제출 프레임명`, 등급(저작 순서)
- ⑦: `제출 프레임명` 목록(누락 검증 키)
```

## 금지
- 입력에 없는 값을 지어내지 않는다. **화면마다 PRD 원문 인용이 없으면 그 화면은 만들지 않는다.**
- **특정 PRD 전용 하드코딩 금지.** 고유명사("당근"·"에어비앤비"), 고정 화면 개수, 고정 절 번호를 지침·코드에 박지 않는다.
- P2를 P0로 올려 적지 않는다. 등급 인플레는 예산을 태운다.
- 다른 단계의 출력 파일을 쓰지 않는다.
